# ADR-0001: Application stack

**Status**: accepted

Date: 2026-11-25. Inherited from the rubens codebase, which ringmaster was scaffolded
from; the choices below were made there and are kept here.

ringmaster runs on Cloudflare Workers, with each organization's data in a SQLite
Durable Object ([ADR-0008](./0008-cloudflare-workers-one-object-per-organization.md)),
and staff sign in through Clerk ([ADR-0009](./0009-staff-sign-in-through-clerk.md)).

| Concern     | Choice                                                  |
| ----------- | ------------------------------------------------------- |
| Framework   | TanStack Start (React 19) on Cloudflare Workers         |
| Toolchain   | Vite+ (`vp`): Vite, Vitest, Oxlint, Oxfmt, Rolldown     |
| Database    | SQLite in one Durable Object per organization           |
| ORM         | Drizzle, with SQL migrations generated by `drizzle-kit` |
| Auth        | Clerk, organization and roles on the user               |
| Client data | TanStack Query; TanStack Form and Table for UI          |
| Validation  | Zod 4                                                   |
| Dates       | `date-fns` 4 and `@date-fns/tz`                         |
| UI          | shadcn/ui on Base UI and Tailwind 4                     |

## Why each, where it was a real trade-off

- **TanStack Start over React Router and Next.js.** Screens keep their state in the
  URL (filters, search, the page of a list), and TanStack Router validates and types
  search params end to end. The app is behind login, so Next.js's strengths (RSC,
  static rendering) buy nothing, and its build is not Vite. TanStack Start was taken
  knowing it churns faster than React Router.
- **Vite+.** It is one CLI over tools that would otherwise run separately. It is
  young; the escape hatch is cheap because every piece underneath is the plain upstream
  tool.
- **Drizzle over Prisma.** Drizzle sits closest to SQL, runs on Durable Object
  SQLite storage, and generates plain SQL migrations.
- **TanStack Form over React Hook Form.** Fits Start's server functions; one Zod
  schema validates on both sides.
- **Base UI under shadcn/ui, not Radix.** shadcn 4's CLI defaults to Base UI
  (`base-nova`).

Governs: `package.json`, `vite.config.ts`, `components.json`
